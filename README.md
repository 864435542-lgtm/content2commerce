## A. 招聘方速览

<a id="project-contribution"></a>

### A1. 项目摘要与个人贡献

面向海外护肤内容与跨境电商运营，本项目以模拟数据演示从 TikTok、Instagram 内容表现，到网站会话漏斗、运营假设与 A/B 实验规划的分析流程。通过统一 ER、CTR、CVR 口径、校验异常数据并公开证据限制，展示运营分析与工具化思路，不代表真实品牌投放、经营业绩或实验成功。

项目重点是业务分析方法与验证意识；代码开发、修改及自动化测试通过 Codex 辅助完成，不表述为独立手写全部代码。

#### 我的项目贡献

- **业务场景定义：**确定海外护肤内容运营与跨境电商分析场景，围绕内容表现、网站转化和下一步行动提出需求。
- **分析流程规划：**规划 Overview、Content Analytics、Traffic & Conversion、Insights、Experiments 五个页面，串联观察、分析、假设与实验记录。
- **指标与质量要求：**明确 ER、CTR、CVR 及漏斗指标的计算口径、有效数据条件、异常排除与零分母处理，并提出验证要求。
- **洞察结构设计：**设计数据事实、未验证的可能原因、建议行动与验证计划的分层展示，要求公开样本量、日期覆盖和归因限制。
- **实验流程规划：**规划 A/B 对照方案、基线、周期、成功标准、可选结果与复盘逻辑，区分模拟演练、用户自报与已核验结论。
- **AI 辅助实现与验收推进：**使用 Codex 辅助代码实现、迭代及自动化测试，制定并推进浏览器验收；具体通过范围以实际验收记录为准，不将测试通过等同于全部浏览器验收通过。

### A2. 业务目标和五页功能

- **内容表现（Content Performance）：**查看护肤教程、产品展示、成分标签阅读、使用场景等模拟内容的曝光、互动与链接点击。
- **网站转化（Website Conversion）：**拆解访问、加购、到达结账、完成购买四阶段会话漏斗。
- **运营洞察（Operational Insights）：**区分数据事实、未验证原因与建议，公开样本和数据限制。
- **实验规划（Experiment Planning）：**记录假设、对照方案、测试周期和成功标准，支持手工结果与复盘。

<a id="simulation-case"></a>

### A3. 模拟运营分析案例：护肤电商加购至购买观察

1. **业务问题：**如何识别护肤电商购买流程中值得检查的环节？
2. **数据观察：**2026-10-01 至 2026-10-28 模拟会话数据：加购 3,094、购买 845，完成率为 845 ÷ 3,094 × 100% ≈ 27.31%，由有效日记录先汇总再计算；无基准，不能判断好坏。
3. **运营假设：**运费说明时机、结账复杂度可能影响决策，尚无证据证明。
4. **建议行动：**先检查流程、费用说明和行为数据，不直接下因果结论。
5. **验证方案：**拟随机分配会话，对照组保持原运费说明时机，实验组仅提前展示。主要指标为网站购买 CVR，完成率作辅助；事前约定周期、样本计划和最小有用差异，再按预定规则判断，不预设成功或显著性。
6. **证据限制：**方案未执行；数据不能识别个体放弃原因，也不能证明社媒内容带来购买。

<a id="key-boundaries"></a>

### A4. 关键限制

- **模拟数据：**分析仅用于个人作品展示，不是品牌投放、经营成绩或产品功效证据。
- **无购买归因：**社媒点击与网站购买没有共享归因键，不能直接关联或推断因果。
- **平台与形式混杂：**Instagram 全为 Carousel，TikTok 全为 Video，无法分离两者影响。
- **实验未经验证：**案例 A/B 方案尚未执行；Simulation 为模拟演练，Actual 仅为用户自报、未经核验。Completed 不等于成功。

本项目展示将海外护肤内容运营问题转化为可操作工具的能力：建立指标字典、控制数据质量、拆解会话漏斗、区分观察与因果、提出可验证假设，并管理实验计划及复盘。价值在于分析方法、证据透明度和工具化实践，不在于模拟数字大小；不宣称真实 GMV、ROI、增长、投放经历或实验成功。

## B. 技术与复现附录

<a id="metrics-quality"></a>

### B1. 指标字典与数据质量

以下公式均乘以 100% 并保留两位小数；整体比率先汇总对应有效记录的分子、分母，再相除，不直接平均单条或每日比率。

| 指标 | 分子 | 分母 |
| --- | --- | --- |
| **ER · Engagement Rate** | 有效内容的互动总量 `engagements` | 同批内容的曝光总量 `impressions` |
| **CTR · Link Click-Through Rate** | 有效内容的链接点击总量 `clicks` | 同批内容的曝光总量 `impressions` |
| **CVR · Purchase Conversion Rate** | 有效网站日记录的购买会话总数 | 同批日记录的网站会话总数 |
| **访问 → 加购** | 加购会话 | 网站会话 |
| **加购 → 结账** | 到达结账会话 | 加购会话 |
| **结账 → 购买** | 购买会话 | 到达结账会话 |
| **加购 → 购买完成率** | 购买会话 | 加购会话 |
| **漏斗阶段占全部会话** | 对应阶段会话 | 网站会话 |

#### 校验与零值

- **ER：**仅使用互动与曝光均为有限非负数字的内容；**CTR：**仅使用点击与曝光均为有限非负数字的内容。缺失值、字符串、负数、NaN、Infinity 被排除。两个指标独立校验，缺失点击不影响有效 ER。
- **网站漏斗：**四个数量必须全部为有限非负整数，并满足 `sessions ≥ cart ≥ checkout ≥ purchases`，否则排除整条日记录，不调整原数值。网站 KPI、CVR、漏斗、网站趋势及相关 Insights 共用有效集合。
- 真正的数字 **0 有效**。相关比率分母为 0、没有有效记录或汇总数值无法计算时显示 **N/A**；分母大于 0、分子为 0 时显示 **0.00%**。
- 日期先独立校验。无效日期排除并提示；开始日晚于结束日返回错误，不偷偷交换日期。无效日期的排除数与指标字段的排除数分别说明。
- ER 的互动口径为点赞、评论、分享、收藏，但数据只保存模拟互动总数，没有四类明细。链接点击独立保存。
- 网站单位为**会话（Sessions）**，不是独立用户、订单或事件次数；演示假设每个会话在每阶段最多计一次，后阶段属于前阶段子集，没有真实会话追踪明细。
- 校验是按指标实施的；不应将所有原始总量卡片、图表理解为都经过同一套 ER／CTR 校验。

完整 28 天的数值用于复现检查，**不是业务成绩**：

| 内容数 | 曝光 | ER | CTR | 网站会话 | 加购 | 结账 | 购买会话 | CVR |
| ---: | ---: | ---: | ---: | ---: | ---: | ---: | ---: | ---: |
| 28 | 620,200 | 4.29% | 1.07% | 28,364 | 3,094 | 1,666 | 845 | 2.98% |

14 天 CVR 为 3.04%，7 天为 3.07%；C20 CTR 为 0.80%，C28 为 1.20%。

### B2. 数据来源、日期覆盖与解释边界

前四页共用日期范围：28 天为 **2026-10-01—2026-10-28**，14 天为 **2026-10-15—2026-10-28**，7 天为 **2026-10-22—2026-10-28**，包含首尾，不依赖电脑当前日期。底层支持完整日期、跨月、跨年和闰年校验；界面没有自定义日期选择器。Experiments 独立于分析日期筛选。


- 分析数据在 `src/data.ts` 按固定规则生成：28 条社媒内容及 28 条网站日记录，日期为 2026-10-01 至 2026-10-28。七个护肤英文标题循环使用，各出现四次；改为护肤标题没有重新生成数值，也不证明某护肤主题产生了这些表现。
- 社媒和网站数据独立生成，没有用户、会话、UTM 或订单归因键。相同日期或同步波动不证明社媒点击导致购买，不能计算真实内容收入、GMV 或 ROI。
- Instagram 全为 **Carousel（轮播）**，TikTok 全为 **Video（视频）**。平台与形式完全绑定，无法独立判断平台或内容形式的影响。
- 覆盖日期数指有效记录出现的**不同日期数量**。首尾日期不代表中间每天都有内容；内容记录数也不等于覆盖天数。趋势合并两个来源的有效日期，缺少来源记录时保留空值，不把缺失当作真实零表现。
- 实验的 **Simulation** 是模拟演练；**Actual — user-reported, unverified** 仅表示用户自行报告，系统没有连接真实数据源核验。

<a id="insights-method"></a>

### B3. Insights 方法与证据结构

三条 Insights 为固定规则和文案模板配合动态数字，不是 AI 分析或预测：

1. 比较当前样本的加权平台 ER；处理原始值相等、四舍五入后相同和不可计算的情况。
2. 展示有效网站样本的加购到购买完成率，不预设行业好坏阈值。
3. 并列展示 CTR 校验后的点击量与有效购买会话，公开两边日期覆盖及无归因限制。

每张卡片保留：

- **DATA FACT · SIMULATED SAMPLE：**分行摘要，包括核心指标、有效／排除记录和覆盖日期数。
- **Data evidence：**默认折叠，展开查看完整日期、公式与排除依据。
- **POSSIBLE REASON · NOT VERIFIED：**待验证解释，不当作已识别原因。
- **SUGGESTED ACTION：**下一步行动建议。
- **VALIDATION PLAN：**假设、主要指标、当前模拟基线、测试设计／周期与成功标准制定方式。

Limited Evidence、N/A 原因、覆盖差异和无归因提醒默认可见。少于两条有效内容／日期、部分排除或来源覆盖不同等会触发相应提示；这些是透明度提醒，**不是行业标准、样本充足证明或显著性检验**。验证计划不预填虚构成功目标，也不会自动创建实验记录。

<a id="experiments-method"></a>

### B4. Experiments 方法与本地保存

#### 计划与状态

必填字段为名称、假设、主要指标，ID 自动生成；名称最多 120 字符、假设最多 500 字符。支持四种主要指标：社媒 CTR、社媒 ER、网站 CVR、加购到购买完成率。

可选计划字段：Control Group、Treatment Group、Baseline（0–100%）、Start Date、End Date、Success Criteria。三个计划文本各限 500 字符；日期需有效，结束日不得早于开始日。旧记录缺少新字段可正常加载。

状态为 Planned / Running / Completed，可手工切换。**Completed 不等于实验实际执行、结果充分或成功**；不强迫用户编造结果。

#### 可选结果与复盘

Result Type、两组曝光／点击、Conclusion、Next Action 默认留空。支持保存部分记录、未执行、证据不足或无法判断的复盘；结论是用户填写，未经核验。

仅 **Social link CTR** 在来源类型已选择、两组四个数量全部有效时自动计算：

- 组内 CTR = 点击 / 曝光 × 100%；曝光为正的安全整数，点击为非负安全整数且不超过曝光。
- 百分点差异 = 实验组 CTR（百分数）− 对照组 CTR（百分数）。
- 相对提升率 =（实验组 CTR − 对照组 CTR）/ 对照组 CTR × 100%；对照组 CTR 为 0 时为 N/A。

例如 1.00% 到 1.50% 是 **+0.50 个百分点、+50% 相对变化**，仅是算术示例。其他主要指标明确提示不支持自动效果计算，不会误用曝光／点击计算 ER 或 CVR。系统不执行实验、不进行显著性判断、不验证成功或因果关系。

#### 存储边界

新增、编辑、改状态及确认删除后立即尝试写入浏览器 `localStorage`，刷新恢复；取消不保存，合法空列表不会重新插入 Demo。首次无保存值时显示两条 Demo 实验。

记录只属于**当前浏览器、设备和网站来源地址**，不自动同步。`localhost` 与 `127.0.0.1`、不同端口相互独立；清除网站数据或使用临时浏览模式可能导致丢失。读取／校验失败时回退 Demo 并暂停写入，保留原文；写入失败会提示临时修改未保存。请先备份损坏原文再处理，避免直接清除有价值记录。

当前没有导出、备份、冲突合并或多标签页同步；后保存的完整列表可能覆盖其他标签页的更新。Insights 验证计划与实验列表是独立模块，没有自动关联。

### B5. 本地运行（Windows）

技术栈：React + TypeScript + Vite、Recharts、Lucide React；无后端。

#### 环境准备

需要 Node.js 及可用的包管理器。Vite 7 要求 Node.js 20.19+ 或 22.12+；本项目此前实际运行于 Node.js **24.22.1**。先在新的 PowerShell 中检查：

```powershell
node --version
npm --version
pnpm --version
```

npm 与 pnpm 不必同时存在。若提示 `node` 无法识别，请先确认 Node 安装目录及 PATH，重新打开终端；这不是实验数据或项目代码错误。不要将 Codex 自带缓存路径当作通用安装位置。

#### 安装依赖与启动

仓库保留 `pnpm-lock.yaml`，此前使用 pnpm 11.25.0 安装，建议使用可用的 pnpm 以锁文件复现：

```powershell
cd G:\content2commerce
pnpm install --frozen-lockfile
pnpm run dev
```

`pnpm-workspace.yaml` 允许 esbuild 构建脚本。安装需要访问软件包仓库，首次安装需联网。

若只有 npm，可使用以下替代方式；它不会使用 pnpm 锁文件，解析版本可能不同，也可能生成 package-lock.json，不能视为完全相同的锁定安装：

```powershell
cd G:\content2commerce
npm install
npm run dev
```

已安装依赖且普通 Windows 环境能找到 `node` 时，可双击 `start.cmd`。该脚本直接运行本地 Vite，不依赖 npm／pnpm，也不会自动安装依赖。Codex 终端能找到 node，不代表资源管理器双击时也能找到。

浏览器访问终端打印的 Local 地址，通常为 `http://127.0.0.1:5173/`；端口占用时会顺延。保持终端打开，Ctrl+C 停止。运行期不需要连接真实业务服务。

#### 构建与生产预览

```powershell
pnpm run build
pnpm run preview
```

npm 环境对应 `npm run build`、`npm run preview`。build 执行 TypeScript 检查后生成 `dist/`；preview 预览已构建产物，使用终端打印的地址。它们不代表已部署公开网站。

### B7. 已知限制与后续方向

- 样本规模、循环主题、模拟性质及平台混杂等解释限制见 B2；这些数据不能替代真实业务证据。
- 分析日期选项固定；不支持真实归因、统计显著性、自动实验执行或自动结果验证。
- 网站只有日汇总；部分原始社媒总量展示没有独立数值清洗，不能将 Demo 的校验能力等同于生产数据管道。
- 实验仅本地保存，无导出备份、多标签页冲突保护或跨设备同步；状态不受结果完整性约束。
- 浏览器视觉、窄屏与键盘验收仍需按清单记录；没有附上不存在的截图或在线部署链接。

后续优先考虑完成并记录浏览器验收、整理带 Demo 标识的作品截图、增加本地实验备份与冲突提醒；如接入真实数据，需先定义字段口径、授权和归因规则，再讨论效果分析。暂不以增加页面或虚构成功案例替代证据完善。
